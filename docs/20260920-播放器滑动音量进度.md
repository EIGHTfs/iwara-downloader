## 一、修改目标

- **问题描述**：播放页（移动端为主）缺少手势音量控制——上下滑动音量（B 站/H5 播放器通用手势）不存在；左右滑动进度已由 `play-enhance.js` 的 `initDragSeek` 实现，但**按位移比例映射到整段时长**（`ratio * duration`），细粒度控制差，且**与音量手势抢占同一通道**（当前左右/上下滑动全部进了 seek）。
- **期望效果**：
  1. **上下滑动实时音量**：在播放器画面上下滑动，实时调音量（有 HUD 反馈：音量百分比），松手不跳变；
  2. **左右滑动进度连续化**：左右拖动 seek 保持连续（已有），微调：竖滑永远是音量、横滑永远是进度，互不抢占；位移 → 音量/进度的映射带阻尼与钳制；
  3. 与现有交互不冲突：单击暂停、600ms 长按 3x 快进、长按抑制右键菜单、控制条区域不触发手势。
- **成功标准**：
  1. 竖滑 ↑ 音量 +，竖滑 ↓ 音量 -；音量有 HUD 显示；音量 0↔1 钳制，不越界
  2. 横滑进度连续 seek，进度 HUD 显示当前时间/总时长
  3. 横竖判定（首个位移方向决定模式）后不再切换模式，避免抖动
  4. 播放器控制条 / 进度条区域滑动不触发画面手势（现有 `.art-bottom` 排除保留）
  5. 移动端与桌面端（鼠标）都可用；不影响现有单击/长按/右键
- 遵循用户偏好「bugfix-auto-authority」：本项属交互增强（新功能），写计划等确认后再实现。

## 二、潜在问题分析

| 风险类型 | 可能性 | 影响 | 缓解措施 |
|----------|--------|------|----------|
| 手势方向歧义/误触 | 中 | 单击、长按、滑动三者边界模糊，误调音量/进度 | 方向锁定：首个超过阈值（如 12px）的位移决定横/竖模式，模式内不再切换；位移阈值区分「滑」与「点」 |
| 音量无反馈 | 中 | 用户不知当前音量 | HUD 浮层（复用 art.notice 或自绘音量条浮层），拖动期间持续更新 |
| 与 initDragSeek 冲突 | 中 | 现有横滑 seek 与新手势叠加 | 重构 initDragSeek 入口：统一手势分发器（方向判定 → seek 或 volume），单点接入 |
| 与 600ms 长按快进冲突 | 中 | 按住不动 600ms = 快进；先滑动 = 手势 | 现有 `clearHold` 契约保留：进入拖动/手势（位移超阈值）即取消长按计时 |
| 触摸滚动吞事件 | 高 | 页面可能随滑动滚动 | 现有 `touch-action:none` 已设置（initDragSeek :145），保持；画面是页面唯一滚动区不影响 |
| 播放器音量 persist | 低 | 无音量记忆 | 不扩展本地存储（本次不做音量记忆，可入后续清单） |

**边界条件**：
1. 无视频（art.video 不存在/duration=0）：手势不生效，直接返回
2. autoplay 被拦截（视频 paused 且未 playing）：音量手势仍可用（音量是属性，不依赖播放状态）；进度手势跳过
3. pointercancel / pointerleave 中途退出：复位 ctx，不留脏状态
4. 音量 0 时静音态（muted）与 volume 属性同步：调音量时取消 muted

### 12.4 2026-09-20 进度条触摸滑动补充（用户实测反馈「点进度条可以、滑动没反应」）

> 用户实测：进度条**点击**可 seek，**触摸滑动**无反应。推翻 §12.1 原结论「官方进度条触摸 seek 可用」——那是桌面行为，触摸滑动未覆盖。

**根因分析**（读 ArtPlayer 5.4.0 minified 源码逐行核实）：
1. 官方进度条拖动事件绑定在 **`p||(...)` 分支**内（`p` = 移动端判定/触屏设备判定）：仅非移动端（桌面）绑定 `click`/`mousemove`/`mouseleave`/`mousedown` + `document:mousemove/up`；移动端进度条**不绑任何拖动事件**。
2. 桌面触摸屏（如 Windows 触屏一体机）被归为非移动端（`p=false`），官方绑的是 **mouse 事件**——浏览器把触摸映射为 mouse 事件时，**click 能映射成功**（所以「点可以」），但**滑动（mousemove）被浏览器默认 `touch-action` 当成页面滚动接管**，mousemove 不连续派发（所以「滑不动」）。

**修复**（`bench-template/server/templates/_iwara-style/public/play-enhance.js` 新增 `initProgressTouch`）：
- `.art-progress`（官方进度条）设 `touch-action:none`——触摸滑动不再被页面滚动/pointercancel 吞掉；
- pointer 触摸通道（**仅 `e.pointerType !== "mouse"` 介入**）：`pointerdown` 按下即跳（与官方点击 seek 一致）+ `pointermove` 按住滑动按 `(clientX - rect.left) / rect.width × duration` 连续 seek + `setPointerCapture` 保证拖出进度条后 pointermove/up 仍派发给进度条；
- 桌面鼠标 `pointerType === "mouse"` 直接放行，仍走官方 mousedown 拖动，互不干扰；
- `enhancePlayer` 中在 `if (IS_MOBILE) return` **之前**调用（移动端也生效）；`art.on("destroy")` 时清除 `touch-action`。

**关联发现**（同批组装时）：模板 `server/templates/_iwara-style/server/lib/like-state.js` 是旧版（无 mtime 字段），组装把项目 1.7.13 的 mtime 版覆盖回退了——已从 git HEAD 恢复项目文件并把 **mtime 版回同步模板**（防下次组装再回退）。教训：**模板与项目同文件出现版本分叉时，组装必然以模板为准覆盖项目侧修复，模板侧改动必须先同步回模板**（模板是权威源）。

**验证**：node --check 全过；iwara 组装产物含 `initProgressTouch`；like-state 模板/项目 mtime 一致；与画面横滑 initDragSeek / 竖滑音量共用方向分发不冲突。提交：bench-template `25d8cac`、iwara `6dfe02e`（README 版本记录 1.7.26+ / 1.7.14）。触摸屏实机滑动验证待用户确认。
