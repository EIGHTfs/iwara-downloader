# 搜索列表

按关键词或时间范围搜索视频，结果分页展示并支持勾选下载；每行显示「已赞」标记。

## 一、接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/search` | 发起搜索（关键词、排序、用户名、时间范围） |
| `GET /api/search-status` | 查询进度与已取得的结果（增量轮询） |
| `POST /api/search/stop` | 停止当前搜索 |
| `GET /api/search/cache` | 读取上次搜索缓存 |
| `POST /api/search/clear` | 清空缓存 |
| `POST /api/search/import` / `save` / `export` | 导入、保存、导出搜索结果 |

## 二、数据流

```
发起搜索
  → 服务端按条件请求远端，逐页写入搜索缓存 json（结果条目 + 进度）
  → 前端轮询 search-status 增量取回结果并追加渲染
  → 服务端在每次返回结果前，用本地状态合并每条的 liked 字段
  → 前端按 liked 渲染「已赞」标记
```

关键点：**结果条目的 `liked` 字段是唯一数据源**。早期实现同时依赖前端内存里的全量已赞集合做兜底，两个来源不同步时会互相覆盖（表现为「有时显示、有时不显示」）。现在只认接口返回的字段，缺失按未赞处理。

## 三、已赞标记的局部刷新

点赞状态会在播放页被改变，搜索列表需要跟随，但不能整表重绘（重绘会导致图片闪烁、滚动位置跳回顶部）。

机制：

1. 本地状态文件变化后，`GET /api/liked-state` 返回的 `mtime` 随之变化（文件修改时间）。
2. 前端轮询时比较 `mtime`，**只有变化才触发局部更新**。
3. 局部更新只遍历当前已渲染的行，按视频 ID 找到对应条目，增删该行的标记节点，不动行内其它内容。

分工原则：

| 变化类型 | 处理方式 |
| --- | --- |
| 结果结构变化（新搜索结果、分页追加、排序切换） | 整表渲染 |
| 仅点赞状态变化 | 局部更新对应行 |
| 无变化 | 不操作 DOM |

## 四、渲染与分页

- 结果按当前排序与筛选条件渲染，每页固定条数，滚动到底部继续加载。
- 每行包含封面、标题、作者、时长、清晰度与勾选框；已赞行显示标记。
- 勾选后可通过下载入口提交到下载队列。

## 五、边界

1. **搜索进行中**：结果持续追加，此时点赞状态变化走局部更新，两者使用同一渲染入口，避免互相覆盖。
2. **本地状态文件不存在或读取失败**：`mtime` 视为 0，标记按未赞渲染，不报错。
3. **条目缺少视频 ID**：跳过更新，不参与局部刷新。
4. **mtime 精度**：同一毫秒内多次写入可能不触发更新；写入本身是用户主动操作，频率低，影响可忽略。
5. **未登录**：搜索本身需要登录；已赞标记在未登录时按本地状态渲染。
