> 本方案仅为设计草案，未实际修改任何代码。请审核确认后，再按方案执行。
> 分四次写：① 取消点赞/取关（已完成）｜② 搜索列表点赞字段 + mtime 刷新（已完成）｜③ 播放器滑动音量与进度（已完成）｜④ 进度条图片预览（本文档）
> 2026-09-20 方案更新：**改用 ArtPlayer 官方 VTT 缩略图插件**（`artplayer-plugin-vtt-thumbnail`），比内置 thumbnails 配置更成熟（官方推荐、支持 VTT 精确坐标、ready 后动态注册避免「初始化后改配置需重建实例」的限制）。

## 一、修改目标

- **问题描述**：播放页进度条拖动时无画面预览——不知道拖到哪一帧。ArtPlayer 官方提供 **VTT 缩略图插件**（`artplayer-plugin-vtt-thumbnail`）：先做一张多帧「雪碧图」（PNG/JPG 网格图）+ 配套 WebVTT 文件（`#xywh=` 指定每帧在雪碧图中的坐标），插件在鼠标悬停进度条时按时间点显示对应区域。本服务**已有完整本地抽帧管线**（`server/lib/thumb-cache.cjs` `extractFrame` + `findFfmpeg` 定位项目 `tool/ffmpeg`），只差把「单帧封面」扩展成「N 帧雪碧图 + VTT」。
- **期望效果**：
  1. 播放页进度条 hover/拖动时，进度条上方显示当前时间点的视频预览图（B 站式）
  2. 雪碧图 + VTT 由**服务端 ffmpeg 本地生成**（不依赖官方接口、离线可控、复用现有管线）
  3. 插件 js 作为第三方静态文件放 `server/public/vendor/`（与 artplayer.js 同目录），模板仓库同步，`assemble.json` 已含 vendor 整目录下发（:63），**无需改 assemble.json**
  4. 已有视频首次进入播放页触发生成；生成中不阻塞播放（无预览不报错）
- **成功标准**：
  1. `GET /api/thumbnail-sprite?id=<vid>` 返回雪碧图（200 image/jpeg），未生成 404
  2. `GET /api/thumbnail-vtt?id=<vid>` 返回 VTT 描述文件（200 text/vtt），未生成 404
  3. `play-info`（或独立接口）返回 `vtt` 元信息 URL；前端在 `art.on("ready")` 里 `art.plugins.add(artplayerPluginVttThumbnail({ vtt }))`
  4. 进度条 hover 显示预览图且位置随进度正确（VTT 坐标精确对应）
  5. 无视频/partial/未生成时不注册插件，页面无 JS 报错；模板仓库 vendor/ 同步后组装产物含插件文件

## 二、官方方案依据（用户提供，2026-09-20）

> 核心插件：**artplayer-plugin-vtt-thumbnail**（ArtPlayer 官方推荐）
> 原理：解析 WebVTT 缩略图描述文件（`#xywh=` 坐标），hover 进度条时按时间点从雪碧图切对应区域。
> 集成：`art.on('ready', async () => { art.plugins.add(artplayerPluginVttThumbnail({ vtt: 'xxx.vtt' })); })`
> 配套：**artplayer-plugin-auto-thumbnail**（浏览器端自动抽帧，免服务端；本次不采用——浏览器 seek 大文件慢、跨域限制）
> 工具：ArtPlayer 官网雪碧图生成器（浏览器本地，不上传）；**本次用服务端 ffmpeg 生成，替代手工/在线生成**
> 注意：ArtPlayer 不支持初始化后动态改 `thumbnails` 配置——**VTT 插件是在 ready 后注册，天然规避此限制**；跨域需 CORS——本服务同源，无跨域

## 三、潜在问题分析

| 风险类型 | 可能性 | 影响 | 缓解措施 |
|----------|--------|------|----------|
| sprite 生成耗时/资源 | 中 | 抽 N 帧拼图（长视频 N=16 约 1~3s ffmpeg、~100MB 内存） | 后台队列生成（复用 inflight 模式），并发 1；生成中不阻塞播放；只对完整视频生成（partial 跳过）；低负载纪律 |
| VTT 时间/坐标漂移 | 中 | 抽帧时间点与 VTT 描述不匹配，hover 显示错帧 | 生成时同一参数写 VTT：帧时间 = `时长/N × (i+0.5)`，坐标 `(i%col)*w, (i/col|0)*h, w, h`，与实际 tile 布局严格一致 |
| 插件文件获取 | 中 | npm/CDN 下载 artplayer-plugin-vtt-thumbnail 不可达 | 先 network-check-before-download 实测 + check-local-before-download 查本地；vendor/ 已吸收 artplayer.js（同源思路）；失败则告知用户待网络 |
| 部分下载视频 | 高 | `.part` 未下完，时长不准/抽帧区域无效 | `info.partial` 时不生成不注册，前端无预览不报错 |
| sprite 文件命名冲突 | 低 | `<id>-thumb.jpg` 与现有 `<id>.jpg` 封面并存 | 独立命名；`listCached`/`pruneUnknownThumbs` 加过滤 `-thumb.jpg`/`-thumb.vtt` |
| 无 ffmpeg 环境 | 中 | 生成失败 | `findFfmpeg()` 兜底空 → 接口 404、前端不注册（优雅降级） |
| 模板仓库改名 | 低 | 原 `dl-server-template` 目录已清空（改名 `bench-template`） | 模板同步路径全部指向 `工作区/bench-template`（git 历史延续，含 59b2078 等提交） |

**边界条件**：
1. 无视频文件 / partial：不生成，接口 404，前端不注册插件
2. 时长 ≤5s：N=1 单帧，column=1
3. 雪碧图已存在：直接返回（mtime 缓存；视频变更后由后续覆盖——本次不做文件监听，入后续清单）
4. 并发同视频：`inflight` Map 串行去重
5. VTT/雪碧图跨域：本服务同源（`/api/thumbnail-*`），无 CORS 问题

## 五、逐文件改动详情

### 5.1 `server/public/vendor/artplayer-plugin-vtt-thumbnail.js`（新增）

- 下载 `artplayer-plugin-vtt-thumbnail` dist（npm/官方 GitHub），本地化到 `server/public/vendor/`（同 artplayer.js 归置，零 npm 依赖；NOTICE.md 记录来源与许可）
- 先 `check-local-before-download`（查本地/仓库有无）+ `network-check-before-download`（实测网络）
- **潜在影响**：无；随 assemble vendor 整目录下发进任何组装项目

### 5.2 `server/lib/thumb-cache.cjs`

- **新增** `spriteDir` 相关：
  - `spritePath(id)` → `THUMB_DIR/<id>-thumb.jpg`；`spriteVttPath(id)` → `THUMB_DIR/<id>-thumb.vtt`
  - `spriteExists(id)`（jpg 校验同 hasThumb）；`readSprite(id)`
  - `extractSprite(videoPath, outPath, duration)`：ffmpeg 抽 N 帧拼雪碧图 + 写 VTT——
    - N = `clamp(round(duration/30), 4, 16)`（≤5s → 1；>8min → 16）
    - ffmpeg：`-i video -vf "scale=160:-2,select='not(mod(n\,F))'" -frames:v N` 或按 `-ss` 逐帧；优先 `-filter_complex tile=Nx1` 一步拼图（先实测 tool/ffmpeg 的 tile 可用性，不行退回逐帧 `-ss` + 本地拼接）
    - VTT：`WEBVTT` + 每帧 `HH:MM:SS.mmm --> HH:MM:SS.mmm` + `url#xywh=x,y,w,h`（x=(i%col)*w, y=(i/col|0)*h, w=160, h=按视频比例取整）
    - 与 extractFrame 同款：20s 超时、SIGKILL、tmp+rename、失败清理
  - `generateSprite(id, videoPath, duration)`：`inflight` 去重 + `spriteExists` 短路 + 后台 Promise（路由/play-info 触发）
- **`listCached`** :312 过滤加 `!n.endsWith("-thumb.jpg") && !n.endsWith("-thumb.vtt")`，防 warmup 扫到雪碧图当封面 id 或误删
- **改动原因**：雪碧图 + VTT 数据源

### 5.3 `server/routes/play.js`

- 新增 `GET /api/thumbnail-sprite?id=`（image/jpeg）与 `GET /api/thumbnail-vtt?id=`（text/vtt），无则 404
- play-info：完整文件时 `spriteExists` → 附 `thumbVtt: "/api/thumbnail-vtt?id=" + id`；未生成则后台 `generateSprite`（不阻塞响应，返回 null）
- **改动原因**：前端拿 VTT URL

### 5.4 `server/public/play.html`

- vendor 区（artplayer.js 之后）加 `<script src="/vendor/artplayer-plugin-vtt-thumbnail.js"></script>`

### 5.5 `server/public/play-app.js`

- `initPlayer` 里 `art.on("ready", ...)`：`if (info.thumbVtt && typeof artplayerPluginVttThumbnail === "function") art.plugins.add(artplayerPluginVttThumbnail({ vtt: info.thumbVtt }))`
- 失败静默（插件不存在/无预览时不报错）

### 5.6 模板同步（bench-template，原 dl-server-template 改名）

- `server/templates/_iwara-style/public/vendor/`：复制插件 js + NOTICE.md（assemble vendor 整目录自动下发）
- `server/templates/_iwara-style/public/play.html` / `play-app.js`：同步改动
- **注意**：模板仓库现路径 = `工作区/bench-template`（原 `dl-server-template` 已清空）；git 历史延续
