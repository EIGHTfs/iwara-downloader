# 项目结构与配置

> 项目目录、`server/config.json` 配置项与不入库的用户数据清单。

## 目录结构

```
├── start.sh / start-macos.sh / start-windows.bat / start-windows-background.bat  # 启停脚本（单脚本子命令）
├── stop.sh / restart.sh / status.sh    # 兼容薄壳 → start.sh
├── scripts/iwara-cred-fetch.user.js  # 油猴凭证采集 + 一键发送
├── userdata-manifest.json            # 用户数据文件清单（备份/恢复按此收集）
└── server/
    ├── app.js                        # HTTP 入口（装配 + 鉴权门 + 静态 + 启动）
    ├── boot.cjs                      # 零依赖启动器（强制本项目 .js 按 CommonJS 加载）
    ├── config.js                     # 配置读取
    ├── config.example.json           # 配置样例（入库）；真实 config.json 不入库
    ├── routes/                       # 路由，按域拆分（12 个）
    │   └── auth.js browse.js search.js download.js play.js rename.js
    │       videos.js settings.js account.js data.js index.js auto-update.js
    ├── lib/                          # 功能实现
    │   ├── iwara-api.js              # 远端 API 访问（IP 直连 + 挑战绕过）
    │   ├── downloader.js             # 下载引擎（direct / aria2 + 子域轮换）
    │   ├── thumb-cache.cjs           # 封面缓存 + 缩略图雪碧图生成
    │   ├── like-state.js             # 本地已赞 / 已关注状态
    │   └── cjs-bootstrap.cjs         # CommonJS 加载引导
    ├── core/ auth/ config/ http/     # 通用运行支撑件，按功能分层
    │   route/ store/ update/ assemble/
    └── public/                       # 网页前端
```

两部分的区别：`core/` `auth/` `config/` `http/` `route/` `store/` `update/` `assemble/` 以及 `boot.cjs`、`lib/cjs-bootstrap.cjs`、`lib/start.sh` 属于**通用运行支撑件**，与具体业务无关，可整体替换；`routes/`、`lib/` 下的其余文件与 `app.js` 属于**本项目业务实现**。命名上也能看出来：支撑件按功能子目录（`http/path-safe.js`），业务件按领域（`lib/downloader.js`）。

## 配置（server/config.json）

记录：**端口、凭证、下载路径、文件名规则、后端（direct / aria2）**。

```json
{
  "port": 8643,
  "iwaraToken": "",
  "iwaraCookie": "",
  "downloadBackend": "direct",
  "downloadPath": "/path/to/your/Iwara/",
  "fileNameTemplate": "Iwara_-_{TITLE}_[{ID}]_[{QUALITY}]"
}
```

> ⚠️ **安全说明**：仓库只提交 `server/config.example.json`（示例路径、空凭证）。
> 真实配置（含 token / cookie / 本机路径 / 密码哈希）保存在本地 `server/config.json`，已被 `.gitignore` 忽略，**不会上传**。
> 首次使用：复制 example 为 `config.json` 后填写，或在网页「设置」中保存。

### 常用字段

| 字段 | 说明 |
| --- | --- |
| `port` | HTTP 端口（默认 8643） |
| `iwaraToken` | 刷新令牌（油猴脚本复制） |
| `iwaraCookie` | 完整 Cookie（含 `cf_clearance`；HttpOnly 项需油猴 `GM_cookie` 读取） |
| `iwaraUA` | 请求 User-Agent；留空用内置精简 UA。`cf_clearance` 与生成它的浏览器 UA 绑定，因此回传凭证时应一并回传 UA |
| `downloadBackend` | `direct`（默认）或 `aria2` |
| `downloadPath` | 下载根目录。`direct` 为本机路径；`aria2` 为 **aria2 所在机器**上的路径 |
| `fileNameTemplate` | 文件名规则，变量见下表 |
| `concurrency` | 直连并发数 |
| `aria2Path` / `aria2Token` | aria2 JSON-RPC 地址与密钥（密钥不含 `token:` 前缀，代码会自动补） |
| `aria2Dns` | 交给 aria2 的 DNS 服务器，留空则用其默认 |
| `playPublic` | 播放页与播放接口是否免登录（默认开启；关闭后需登录） |
| `showLikedInSearch` | 搜索列表是否显示「已赞」标记 |
| `autoLike` / `autoFollow` | 下载时是否顺带点赞 / 关注 |
| `checkDownloadLink` | 下载前是否校验直链可用 |
| `iwaraCfgIp` / `hostSuffix` | 直连边缘 IP 与 Host 后缀（挑战绕过用） |
| `pageProxySites` | 页面代理站点列表（备用通道） |
| `sessionHours` | 登录会话有效期（小时） |
| `useAuthorSubdir` | 历史开关，保留在配置结构中；作者目录现在由文件名规则里的 `{AUTHOR}/` 控制，不再单独生效 |

### 文件名规则变量

| 变量 | 含义 |
| --- | --- |
| `{TITLE}` | 标题 |
| `{ALIAS}` | 别名 |
| `{ID}` | 视频 ID |
| `{AUTHOR}` | 作者 |
| `{QUALITY}` | 清晰度（如 Source / 540） |
| `{UPLOADTIME}` | 上传时间 |
| `{NOWTIME}` | 当前时间 |

默认：`Iwara_-_{TITLE}_[{ID}]_[{QUALITY}]`（不要写扩展名，落盘自动补 `.mp4`）

规则里的 `/` 直接作目录分隔：写 `{AUTHOR}/Iwara_-_{TITLE}_[{ID}]` 即按作者分目录，不写则存下载根目录。

**必须含 `{ID}`**：封面 `server/thumbs/<id>.jpg`、同名 sidecar json、视频文件都靠这个 ID 对上。设置页保存时缺 `{ID}` 会拒绝。

例：`Iwara_-_耀佳音与知更鸟摇一摇_[ZsvQjWn9XNQvAy]_[Source].mp4`

## 用户数据（不入库）

清单见 `userdata-manifest.json`。主要包括：

| 文件 | 说明 |
| --- | --- |
| `server/config.json` | 凭证、路径、密码 |
| `json/download_task.json` | 任务进度 |
| `json/cdn_hosts_state.json` | CDN 成功/失败子域（运行中自动写） |
| `json/search_cache.json` / `search_task.json` | 搜索记录与按时间搜索任务 |
| `json/following_cache.json` | 关注列表增量缓存 |
| `json/liked_state.json` | 本地已赞 / 已关注状态（搜索标记与播放页按钮共用） |
| `json/profile/` | 作者信息索引（含总表） |
| `avatar/<作者ID>/<作者ID>.jpg` | 作者头像（搜索/下载时自动更新） |
| `server/server.log` | 日志 |

备份时按清单复制即可；不要把这些文件提交到 git。
