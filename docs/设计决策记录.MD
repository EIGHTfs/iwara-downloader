# 设计决策记录

记录项目在关键问题上的选择：有哪些候选、为什么选这个、落在哪篇文档。只记录结论与依据，不记录过程。

---

## 一、播放器手势：seek 采用哪种模式

**问题**：按住画面左右拖动时，画面与进度条应该怎样响应。

| 方案 | 行为 | 结论 |
| --- | --- | --- |
| 连续 seek | 拖动中按 0.05 秒粒度不断跳转 | 不采用：播放中连续 seek 反复触发缓冲，画面抖动明显 |
| 缩略图预览 + 松手跳转 | 拖动中只显示小图，松手才跳 | 不采用：拖动过程中看不到进度条时间，操作反馈滞后 |
| **scrub 实时 seek** | 拖动中实时跳转并更新进度条/时间，粒度取整到秒 | 采用 |

**依据**：拖动过程要能直接看到「拖到哪里」，进度条时间必须实时跟随；把粒度收敛到整秒后，同一秒内不重复 seek，既保留实时感又压住 seek 频率；播放中拖动先暂停、松手恢复，避免连续缓冲。

**落点**：`视频页.MD` §4.5

## 二、手势方向判定

**问题**：横滑 seek 与竖滑音量共用画面区域，如何避免互相抢占。

| 方案 | 结论 |
| --- | --- |
| 各模块独立监听、各自判定 | 不采用：同一手势会被两个模块同时响应 |
| 统一手势分发器单入口 | 部分采用：方向判定集中在竖滑模块，横滑模块消费判定结果 |
| **阈值 + 方向锁定，共享状态对象** | 采用 |

**依据**：首个位移超过 12px 才锁定方向（区分「点」与「滑」），锁定后不切换，避免方向抖动；两个模块通过同一状态对象互斥，进入手势即取消长按计时与「点击即播」。

**落点**：`视频页.MD` §4.6、§4.8

## 三、移动端长按快进

| 方案 | 结论 |
| --- | --- |
| 桌面与移动端都用自绘长按 | 不采用：与播放器官方快进同时生效，出现双份加速 |
| **桌面自绘、移动端用官方** | 采用 |

**依据**：播放器在移动端自带长按快进，再自绘一套会重复触发；桌面端官方没有该行为，需要自绘。

**落点**：`视频页.MD` §4.4

---

## 四、进度条触摸滑动

**问题**：触摸屏上进度条「点击可以、滑动没反应」。

| 方案 | 结论 |
| --- | --- |
| 依赖播放器官方拖动 | 不可行：官方只在桌面绑定鼠标事件，移动端不绑定；触摸滑动还会被浏览器当成页面滚动 |
| **给进度条补指针事件通道** | 采用 |

**依据**：设 `touch-action: none` 阻止滚动接管，仅非鼠标指针介入，按下即跳、滑动连续 seek、指针捕获保证拖出后不丢尾段；鼠标仍走官方逻辑。

**落点**：`视频页.MD` §4.7

## 五、进度条缩略图

| 方案 | 结论 |
| --- | --- |
| 播放器 `thumbnails` 初始化配置 | 不采用：只能在初始化时注入，运行期无法追加 |
| 浏览器端自动抽帧 | 不采用：大文件 seek 慢、跨域受限 |
| **服务端生成雪碧图 + VTT，前端插件读取** | 采用 |

**依据**：生成一次长期复用，前端零额外计算；插件在播放器 `ready` 后注册，绕开「初始化后不能改缩略图配置」的限制。

**落点**：`进度条缩略图.MD`

## 六、缩略图抽帧方式

| 方案 | 结论 |
| --- | --- |
| 按固定间隔取帧的滤镜，一次性抽帧 | 不采用：需要整片解码，长视频超时（10 分钟视频超过 60 秒） |
| **输入 seek 逐帧抽取，再拼图** | 采用 |

**依据**：单帧耗时降到 0.2~0.3 秒，总耗时与视频长度基本无关；拼图与 VTT 用同一组参数生成，坐标不漂移。

**落点**：`进度条缩略图.MD` §3.2

## 七、搜索列表「已赞」的数据来源

| 方案 | 结论 |
| --- | --- |
| 前端内存里的全量已赞集合 | 不采用：与接口字段两个来源不同步，出现「有时显示有时不显示」 |
| **接口返回结果里的 `liked` 字段（单一数据源）** | 采用 |

**依据**：服务端在返回前用本地状态合并字段，前端只认字段；缺失按未赞处理，不误亮。

**落点**：`搜索列表.MD` §二

## 八、点赞状态变化时如何刷新列表

| 方案 | 结论 |
| --- | --- |
| 整表重绘 | 不采用：图片闪烁、滚动位置跳回顶部 |
| 轮询无条件重绘 | 不采用：无变化也在消耗渲染 |
| **比较状态文件修改时间，变化才局部更新** | 采用 |

**依据**：状态接口返回文件修改时间，前端比较后才更新；只改变化行的标记节点，不动其它内容；结构变化（新结果、分页）才整表渲染。

**落点**：`搜索列表.MD` §三

## 九、静态资源的版本号

**问题**：改了前端文件，浏览器仍使用缓存中的旧文件。

| 方案 | 结论 |
| --- | --- |
| 按文件修改时间生成版本号 | 不采用：批量落盘时多个文件修改时间相同，版本号不变，缓存不失效 |
| 手写版本号 | 不采用：容易忘记，且脚本与样式各写一套 |
| **按内容哈希生成，脚本与样式统一覆盖** | 采用 |

**依据**：内容一变哈希必变、地址必变，浏览器必然拉新；拼装时自动注入，无需手写。

**落点**：`架构与数据流.MD` §前端组织

## 十、点赞/关注按钮

| 方案 | 结论 |
| --- | --- |
| 单向按钮（只能点赞/关注，不能取消） | 不采用：无法撤销误操作 |
| **同一按钮开关（按当前状态决定请求方法）** | 采用 |

**依据**：按钮携带当前状态，已开启时发取消请求、未开启时发开启请求；每次点击后冷却 3 秒，避免连击真实接口。

**落点**：`点赞与关注.MD` §二

## 十一、索引存储格式

| 方案 | 结论 |
| --- | --- |
| 单个 JSON 文件 | 不采用：整份重写，规模变大后写入放大、崩溃易损坏 |
| SQLite | 不采用：引入原生依赖，与零依赖目标冲突 |
| **JSONL 追加 + 总表** | 采用 |

**依据**：追加写入成本低、可逐行校验、损坏时可截断到最后一条完整记录；总表与明细分离，读取路径只需加载总表。

**落点**：`索引存储技术文档.MD`

---

## 十二、作者子目录

| 方案 | 结论 |
| --- | --- |
| 独立的「按作者建子目录」开关 | 不采用：与文件名规则各管一半，组合行为不直观 |
| **文件名规则里的 `/` 直接作目录分隔** | 采用 |

**依据**：一条规则同时表达目录与文件名，写 `{AUTHOR}/...` 即按作者分目录，不写则存根目录；实现上按段清理非法字符，避免整串替换把分隔符吃掉。

**落点**：`项目结构与配置.MD` §文件名规则变量

---

## 十三、封面地址是否带时间戳

| 方案 | 结论 |
| --- | --- |
| 每次访问追加时间戳强制刷新 | 不采用：刚更新的封面会被旧图覆盖，且刷新后行为不一致 |
| **固定地址 `/api/thumb?id=<ID>`** | 采用 |

**依据**：封面更新由服务端控制写入时机，前端不需要用时间戳绕过缓存；固定地址让同一视频的封面在各页面表现一致。

**落点**：`视频页.MD` §六
