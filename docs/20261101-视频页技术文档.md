# 视频页技术文档

本文覆盖播放页（`/{id}`，内部称视频页）的完整实现：页面组装、播放器初始化、手势系统、进度条图片预览、点赞/关注状态按钮、播放列表，以及服务端缩略图生成链路。所有描述以当前代码为准，涉及文件路径均为相对项目根。

---

## 一、概述

视频页是一张单页播放界面，承担四件事：

1. 播放本地已下载的视频文件（支持边下边播）；
2. 提供接近视频网站的操作手感（倍速、长按快进、画面滑动手势、进度条缩略图预览）；
3. 展示视频元信息与作者信息，并提供点赞/关注（可取消）操作；
4. 侧栏播放列表支持排序、文件夹分组折叠、自动连播与增量加载。

页面不引入前端框架，全部为原生 DOM + ArtPlayer 播放器库，脚本以普通 `<script>` 顺序加载、共享 `window` 全局。

## 二、文件分工

| 文件 | 职责 |
| --- | --- |
| `server/public/play.html` | 页面骨架（片段组装产物）：播放器容器、标题/作者/标签区、点赞关注按钮、播放列表容器、排序控件 |
| `server/public/play-app.js` | 主控：id 解析与 URL 规范化、播放器初始化、元信息渲染、状态按钮、切换视频、错误提示 |
| `server/public/play-enhance.js` | 交互增强：倍速按钮、点击即播、菜单抑制、长按快进、画面横滑 scrub seek、竖滑音量、进度条触摸滑动 |
| `server/public/play-list.js` | 播放列表：排序维度/方向、文件夹分组渲染与折叠、自动连播开关、偏好持久化、增量加载 |
| `server/public/vendor/artplayer.js` | 播放器内核（本地化，零 npm 依赖） |
| `server/public/vendor/artplayer-plugin-vtt-thumbnail.js` | 进度条缩略图预览插件（官方 UMD 版本，本地化） |
| `server/routes/play.js` | 视频页相关路由：播放流、play-info、缩略图雪碧图与 VTT、头像 |
| `server/lib/thumb-cache.cjs` | 封面缓存 + 雪碧图/VTT 生成（ffmpeg 抽帧与拼图） |

脚本加载顺序（`play.html` 尾部，顺序有依赖）：

```
theme-init.js → /vendor/artplayer.js → /vendor/artplayer-plugin-vtt-thumbnail.js → play-list.js → play-enhance.js → play-app.js
```

`play-list.js` 与 `play-enhance.js` 只定义函数，函数体运行时才引用 `play-app.js` 的顶层全局，因此先加载不报错；`play-app.js` 末尾自行执行入口。

## 三、页面加载链路

### 3.1 请求到 HTML

1. 浏览器请求 `/{id}`（也支持 `/play?id=xxx`、`/play#xxx`）。
2. 服务端按片段组装 `play.html`：`@frag:xxx` 指令展开为片段文件内容，`@brand:key` 替换品牌值。
3. 组装器对页面内本地资源做版本化：`<script src="*.js">` 与 `<link href="*.css">` 统一追加 `?v=<内容 md5 前 8 位>`，文件内容一变 URL 即变，浏览器自动拉新（详见 `fragment-assembler.js` 的 `versionizeScripts`）。
4. HTML 响应头 `Cache-Control: no-cache`；静态资源走 `max-age` 缓存，但 URL 已带内容指纹，改动不会读到旧文件。

### 3.2 前端初始化时序

```
脚本加载完成
  └─ play-app.js 末尾入口
       ├─ 解析 id：路径段 → hash → query（三者都无则请求 /api/index 取最新一条并 replace 跳转）
       ├─ setPlayUrl(id)：把地址规范化为 /{id}（replaceState，不产生历史记录）
       ├─ initTheme()：恢复夜间/白天模式与按钮文案
       ├─ bindStateButtons()：绑定点赞/关注点击
       └─ loadVideo(id)
            ├─ fetch /api/play-info?id=...
            ├─ renderVideoMeta(j)：标题、时长、标签、额外信息
            ├─ renderAuthor(j)：作者名 + 头像（头像缺失时按需重试）
            ├─ refreshVideoState(id)：拉取已赞/已关注初始态
            ├─ initPlayer(j, thumbUrl(id))
            └─ renderPlaylist(true)：首次整表渲染列表
```

切换视频时（点击列表项 / 浏览器前进后退 / 自动连播）走 `loadVideo(newId)`：销毁旧播放器实例、重新拉 play-info、重建播放器，列表保持增量状态不重绘。

### 3.3 initPlayer 关键流程

1. `info.hasFile` 为假 → 显示提示（未下载完成 / 无文件）并直接返回，不创建播放器。
2. 已有实例先 `art.destroy(false)`（保留容器），避免多个实例叠加。
3. `new Artplayer(artOptions(info, poster))` 创建实例，挂到 `window.__art` 便于调试。
4. 移除 video 元素的 `crossorigin` 属性（本地同源播放，无需 CORS 协商）。
5. 调用 `enhancePlayer(art)` 注入交互增强（失败不影响播放）。
6. 若 `info.thumbVtt` 非空，在 `art.once("ready")` 后注册缩略图插件（插件只能初始化时注入，ready 后注册可规避该限制）。
7. 绑定 `error`（错误文案）、`video:ended`（自动连播）、`video:seeking`（边下边播时限制 seek 上限）。

## 四、播放器配置

`artOptions(info, poster)` 的关键项与取舍：

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `url` | `/api/play?id=<id>` | 走服务端流式接口，支持 Range 与边下边播 |
| `type` | 由文件扩展名推导 | 缺省 `mp4` |
| `poster` | `/api/thumb?id=<id>` | 封面使用稳定 URL（不加时间戳），避免封面被缓存击穿后反复闪 |
| `theme` | 跟随当前主题色 | 与页面夜间/白天模式一致 |
| `volume` | `0.7` | 初始音量 |
| `autoplay` | `true` | 自动播放；被浏览器策略拦截时由「点击即播」兜底 |
| `playsInline` | `true` | 移动端内联播放，不强制全屏 |
| `gesture` | `true` | 官方手势（进度条区域）保留，画面手势由增强层接管，区域不冲突 |
| `fastForward` | `true` | 移动端长按走官方快进，避免自绘长按双份触发 |
| `setting` / `hotkey` / `pip` / `fullscreen` / `fullscreenWeb` / `screenshot` / `aspectRatio` / `playbackRate` | 均开启 | 保留官方控制面板能力 |
| `miniProgressBar` | `true` | 全屏时顶部细进度条 |
| `autoSize` / `autoMini` | `false` | 关闭自动尺寸/自动迷你，避免布局抖动 |

控制条自动隐藏时间被延长：`Artplayer.CONTROL_HIDE_TIME = 8000`（默认 3 秒过短，容易让人以为没有进度条）。

## 五、交互增强（play-enhance.js）

`enhancePlayer(art)` 创建一个每次实例独立的 `ctx` 共享状态对象，然后依次装配七个模块。`ctx` 字段承担模块间互斥（见 5.8）。

### 5.1 倍速按钮

- 控制条右侧新增按钮，文案 `1x/1.25x/1.5x/2x/3x`。
- 点击按 `SPEEDS` 数组循环切换，设置 `art.playbackRate` 并提示。
- 监听 `video:ratechange` 与 `video:play` 同步按钮文案（设置面板或快捷键改速时也保持一致）。

### 5.2 点击即播（自动播放兜底）

- 初始化 800ms 后若仍处于暂停且未在播放，则武装 `ctx.tapArmed`。
- 武装状态下按下画面：立即 `art.play()`，并置 `ctx.suppressTapClick`（80ms）拦截随之而来的 click，否则刚播放又被内核「单击暂停」停掉。
- 与长按互斥：长按要求处于播放中，因此不会互相抢占。

### 5.3 右键/长按菜单抑制

- 按住画面期间置 `ctx.suppressCtxMenu`，在捕获阶段拦截 `contextmenu`，阻断 ArtPlayer 自带的右键面板。
- 松开后延迟 250ms 解除抑制（长按松手瞬间仍可能触发 contextmenu）。
- 右键（`button === 2`）不在拦截范围，桌面右键菜单保留。

### 5.4 长按 3x 快进（仅桌面）

- 桌面端（非移动 UA）按住画面 600ms 且当前正在播放 → `playbackRate = 3`，提示「3x 快进中，松开恢复」。
- 松开/取消/移出画面 → 恢复按下前的倍速，并置 `ctx.suppressClick`（80ms）防止误触发点击暂停。
- 移动端不装配此模块，长按走官方 `fastForward`，避免双份快进。
- 暴露 `ctx.clearHold` 供拖动模块调用：一旦判定为拖动立即取消长按计时，避免拖动超过 600ms 被误判成长按。

### 5.5 画面横滑 scrub seek（1 秒粒度）

目标体验：按住画面左右拖动时，进度条与时间显示实时跟随手指，画面实时跳到对应帧；seek 粒度取整到整秒。

实现要点：

1. `pointerdown`（画面区域，排除控制条 `.art-bottom`）：记录起点 `startX`、当前时间 `startTime`、总时长、画面宽度；设置 `ctx.suppressCtxMenu`；尝试 `setPointerCapture` 保证拖出画面后仍收到事件。
2. `pointermove`（画面元素上）：水平位移超过 10px 才判定进入拖动（`ctx.drag.seeking = true`），同时调用 `ctx.clearHold()` 取消长按计时。
3. `pointermove`（document 级，保证拖出画面继续生效）：按位移比例换算目标时间，`Math.round` 取整到整秒（同一秒内不重复 seek），然后 `art.currentTime = sec`——播放器内部会自动更新进度条与时间显示，并把画面切到目标帧。
4. 播放中拖动的处理：首次进入拖动时记录 `wasPlaying`，随后 `art.pause()` 暂停，避免连续 seek 触发反复缓冲造成画面抖动；原本暂停则保持暂停。
5. `pointerup`：定格到松手位置的整秒；若 `wasPlaying` 为真则 `art.play()` 恢复播放。
6. `pointercancel` / `pointerleave`：清空拖动状态（拖出画面且已进入拖动时不打断）。

边界：目标时间钳制在 `[0, duration - 0.1]`；方向判定与竖滑音量共用 12px 阈值与 `|dx| > |dy|` 规则。

### 5.6 画面竖滑音量

- 方向分发：首个位移超过 12px 时锁定方向，`|dy| > |dx|` 判为竖滑（本模块），否则判为横滑（交给 5.5），锁定后不切换。
- 音量计算：`delta = -dy / (画面高度 / 2)`，上滑增大；结果钳制在 `0..1`，同时写 `art.video.volume` 与 `art.volume`（同步图标与控制条）。
- 音量大于 0 时自动解除静音；每步提示「音量 N%」。
- 通道：桌面走 pointer；触摸端额外绑定 touch 通道兜底（个别环境 pointer 事件不完整），竖滑时 `preventDefault` 阻止页面滚动。
- 控制条区域不触发；播放器锁定时不触发。

### 5.7 进度条触摸滑动

- 背景：官方进度条拖动只绑定鼠标事件，触摸屏上默认 `touch-action` 会把滑动当成页面滚动。
- 实现：给 `.art-progress` 设 `touch-action: none`，补充 pointer 通道（仅 `pointerType !== "mouse"` 介入），按下即 seek，移动持续 seek，指针捕获保证拖出进度条不丢尾段。
- 桌面鼠标仍走官方逻辑，互不干扰。

### 5.8 手势互斥与方向分发

所有画面手势共享 `ctx`，互斥关系如下：

| 场景 | 判定 | 结果 |
| --- | --- | --- |
| 按住不动 < 600ms 松开 | 未超位移阈值 | 点击（暂停/播放，或触发点击即播） |
| 按住 > 600ms 且播放中 | 未超位移阈值 | 长按 3x 快进（桌面） |
| 首个位移 > 12px 且 `\|dx\| > \|dy\|` | 横滑 | 进入 scrub seek，取消长按计时 |
| 首个位移 > 12px 且 `\|dy\| > \|dx\|` | 竖滑 | 调节音量，取消长按计时与点击即播 |
| 拖动中继续位移 | 已锁定方向 | 不切换模式，持续生效 |
| 拖出画面 | 已进入拖动 | 继续跟随（document 级监听 + 指针捕获） |

`ctx` 关键字段：`tapArmed`（点击即播武装）、`suppressTapClick`/`suppressClick`（拦截误触点击）、`holdTimer`/`holdOn`/`holdBase`（长按）、`drag`（横滑状态，含 `startX/startTime/duration/width/lastT/seeking/wasPlaying`）、`volSwipe`（竖滑状态，含 `startX/startY/base/mode`）、`suppressCtxMenu`（菜单抑制）。

## 六、进度条图片预览（VTT 雪碧图）

### 6.1 前端注册

- 触发条件：`play-info` 返回的 `thumbVtt` 非空（完整文件、非边下边播、时长大于 0）。
- 注册时机：`art.once("ready")` 后 `art.plugins.add(artplayerPluginVttThumbnail({ vtt }))`。
- 插件行为：监听播放器 `setBar` 事件，在进度条上方显示对应时间的帧图（从雪碧图按 `#xywh` 裁切），移动端在拖动进度条时同样显示。

### 6.2 服务端生成（`server/lib/thumb-cache.cjs`）

参数计算（`extractSprite`）：

- 帧数 `N`：时长 ≤ 5 秒取 1；否则 `clamp(round(时长 / 30), 4, 16)`。
- 拼图布局：列 `col = min(4, ceil(sqrt(N)))`，行 `row = ceil(N / col)`。
- 帧宽固定 `w = 160`；帧高按原视频宽高比换算并取偶数（`h = round(160 * 原高 / 原宽)`，向下取偶，满足 yuv420 要求）。
- 每帧覆盖时长 `interval = 时长 / N`。

生成流程（两段式，避免整片解码）：

1. 用 `ffprobe` 探测原视频宽高，算出帧高。
2. 第①段：对 `N` 个时间点 `i * interval` 分别执行「输入 seek 抽单帧」——`-ss <t> -i <video> -frames:v 1 -vf scale=160:h -f mjpeg -q:v 4`，并发 2、单次 30 秒超时。
3. 第②段：把 N 张帧图作为多输入，用 `-filter_complex "...concat=n=N:v=1:a=0[v];[v]tile=<col>x<row>" -frames:v 1 -f mjpeg` 拼成一张雪碧图，写入 `<id>-thumb.jpg`。
4. 同步生成 VTT：`WEBVTT` 头 + 每帧「`开始 --> 结束`」时间行 + `spriteUrl#xywh=x,y,w,h` 帧行；坐标 `x = (i % col) * w`、`y = floor(i / col) * h`，与拼图参数同源，不会漂移。
5. 清理临时目录；生成结果用 inflight Map 去重（同一视频并发请求只跑一次），已存在则短路返回。

产物落点：`server/thumbs/<id>-thumb.jpg` 与 `<id>-thumb.vtt`（与封面同目录）。封面索引只收集 `.jpg` 且排除 `-thumb.jpg` 与临时文件，因此雪碧图与 VTT 不会被误当成封面读取或清理。

工具探测：`ffmpeg` / `ffprobe` 走 `server/tool/tool-detect.js`（环境变量 → 项目 `tool/` 与 `tools/` → 系统路径，逐级校验可执行性并带缓存）；wrapper 自带随行库时通过 `LD_LIBRARY_PATH` 注入。

### 6.3 触发时机

`play-info` 在返回 `thumbVtt` 的同时后台调用 `generateSprite(...)`（不阻塞响应）。首次播放时雪碧图可能尚未生成，接口返回 404，插件静默不显示；生成完成后再播放或刷新即出现。

## 七、点赞 / 关注状态按钮

- 初始态：`GET /api/video-state?id=<id>` 返回 `{ liked, following, authorId }`，据此点亮按钮（`data-on`、`on` 类名、文案「❤️ 已点赞 / ✓ 已关注」）。
- 点击行为：按 `btn.dataset.on` 判断当前态，已开启则 `DELETE` 取消，未开启则 `POST` 开启——即同一个按钮做 toggle。
  - 点赞：`POST /api/like`（body `{id}`）/ `DELETE /api/like?id=<id>`
  - 关注：`POST /api/follow`（body `{userId}`）/ `DELETE /api/follow?userId=<id>`
- 冷却：每次点击后按钮禁用 3 秒（`STATE_BTN_COOLDOWN_MS = 3000`），这两个接口会真实调用官方站点，防误点连击。
- 失败处理：后端返回 `ok: false` 时保持原态并提示错误文案；关注按钮在未取得作者 id 时直接提示，不发请求。
- 状态一致性：点赞成功后后端同步写本地点赞状态文件，搜索列表的已赞标记据此更新。

## 八、播放列表（play-list.js）

### 8.1 数据与排序

- 数据源：`/api/index` 返回的 `videos` 映射，转换为 `{ id, title, name, duration, fileId, createdAt, rel }` 数组。
- 排序维度：`time`（按 `createdAt`）或 `name`（按标题，`localeCompare(..., "zh")`）。
- 排序方向：`desc`（默认）/ `asc`。
- 偏好持久化：`localStorage` 三个键——`iwara-play-sort`、`iwara-play-sortdir`、`iwara-play-autonext`。

### 8.2 分组与折叠

- 按 `rel`（相对目录）分组，每组渲染组标题 + 组体，组标题可折叠（`collapsedRels` 记录）。
- 组头缓存挂在模块级 `playlistGroups`，增量加载时复用，避免重复追加同名组头。

### 8.3 增量加载

- 每次渲染 `PAGE_SIZE = 20` 条，滚动到底部继续追加（`displayedCount` 控制）。
- 排序切换或列表数据变化时整表重绘（`renderPlaylist(true)`）；单纯追加时不清空容器。

### 8.4 自动连播

- 开关状态存 `iwara-play-autonext`（默认开）。
- `video:ended` 时按当前排序取下一个视频：`setPlayUrl(next.id, false)` 更新地址（replaceState）→ `loadVideo(next.id)` 重建播放器；列表末尾播完则停止。

## 九、服务端接口清单

| 方法与路径 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET/HEAD /api/play-info?id=<id>` | 公开路由，内部按播放页公开配置检查 | 返回 `{ hasFile, partial, thumbVtt, title, duration, ext, author, avatar, ... }` |
| `GET/HEAD /api/play?id=<id>` | 公开 | 视频流（支持 Range、边下边播） |
| `GET/HEAD /api/thumbnail-sprite?id=<id>` | 公开 | 雪碧图 JPEG，未生成返回 404，命中缓存 `max-age=86400` |
| `GET/HEAD /api/thumbnail-vtt?id=<id>` | 公开 | VTT 文本，未生成返回 404 |
| `GET /api/video-state?id=<id>` | 公开 | 已赞/已关注初始态 + 作者 id（未登录时返回本地状态） |
| `POST /api/like`、`DELETE /api/like?id=` | 需登录 | 点赞 / 取消点赞，成功后同步本地状态 |
| `POST /api/follow`、`DELETE /api/follow?userId=` | 需登录 | 关注 / 取关 |
| `GET/HEAD /avatar/<uuid>/<uuid>.jpg` | 公开 | 作者头像（项目根 `avatar/` 目录） |
| `GET /api/thumb?id=<id>` | 公开 | 封面图（本地缓存优先，缺失时按需抓取） |
| `GET /api/index` | 公开 | 视频索引（列表数据源） |

## 十、已知边界与设计取舍

1. **边下边播**：`play-info` 的 `partial` 为真时，进度条只覆盖已写入部分；拖动到未写入区域会回落到已缓存位置，页面顶部给出提示，并在 `video:seeking` 中把超尾部的 seek 拉回。
2. **封面 URL 保持稳定**：封面统一用 `/api/thumb?id=<id>`，不追加时间戳。历史实现曾用 `&t=时间戳` 强制刷新，结果会把刚覆盖的正确封面立刻替换成旧图，且刷新后行为不一致。
3. **触摸双通道**：pointer 是主通道，touch 仅作兜底（个别环境 pointer 事件不完整）；两通道共用同一套状态，重复触发时以先锁定方向者为准。
4. **拖动期间暂停**：播放中拖动会先暂停，是为了避免连续 seek 造成反复缓冲与画面抖动；松手后按原状态恢复，不改变用户的播放意图。
5. **seek 粒度取整到秒**：拖动时同一秒内不重复 seek，既降低 seek 频率，也符合「1 秒为最小单位」的定位精度。
6. **移动端长按**：使用官方 `fastForward`，自绘长按仅在桌面启用，避免两套快进同时生效。
7. **缩略图依赖 ffmpeg 可执行权限**：部署产物中 wrapper 必须保留执行位，否则抽帧会静默失败（历史上出现过 100644 权限导致生成全部失败）。
8. **雪碧图帧密度**：帧数上限 16，长视频每帧覆盖区间较大（例如 10 分钟视频约 40 秒一帧），预览精度受此限制；如需更细可调 `N` 的计算上限。
9. **插件只能初始化时注册**：ArtPlayer 不支持运行期修改缩略图配置，因此必须在 `ready` 事件内一次性注册。

## 十一、验证方法

- 静态检查：`node --check` 覆盖 `play-app.js`、`play-enhance.js`、`play-list.js`、`thumb-cache.cjs`。
- 页面结构：确认 `play.html` 中脚本顺序正确（vendor → 列表 → 增强 → 主控），组装产物中资源带 `?v=` 内容指纹。
- 手势：桌面端按住画面横拖，观察进度条时间实时变化、画面逐秒跳帧、松手恢复播放；竖滑观察音量提示与图标同步；长按 600ms 观察 3x 与松开恢复。
- 触摸端：真机验证横拖/竖滑/进度条滑动三条通道均不被页面滚动接管。
- 缩略图：播放任意完整视频后请求 `/api/thumbnail-sprite?id=<id>` 与 `/api/thumbnail-vtt?id=<id>`，应分别返回 JPEG 与含 `#xywh` 的 VTT；进度条悬停/拖动应显示对应帧。
- 状态按钮：点赞后刷新页面应保持已点赞；再次点击应取消；连续点击应被 3 秒冷却拦住。
- 列表：切换排序维度/方向后刷新，偏好应保留；播放到末尾应自动切下一个（开关关闭时不切）。
