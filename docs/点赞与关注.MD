# 点赞与关注

播放页与搜索列表的「已赞 / 已关注」状态，以及点赞、关注的开启与取消。

## 一、状态从哪来

远端接口对「列表类」返回的已赞/已关注标记不可靠：列表与搜索接口对已赞视频恒返回 `false`，只有详情接口返回真实值。因此本项目的做法是：

1. **本地状态文件为权威**：`json/liked_state.json` 保存已赞与已关注的集合，读写由 `server/lib/like-state.js` 负责（原子写）。
2. **首次回填**：保存凭证并验证登录成功后，后台拉取一次「我的已赞」与「我的关注」写入本地文件；此后只做增量（点赞/取消时同步增删）。
3. **远端只作校验**：列表与搜索结果返回前，用本地状态覆盖远端给出的假值。

## 二、播放页按钮

### 2.1 初始态

`GET /api/video-state?id=<ID>` 返回 `{ liked, following, authorId }`。该接口为公开路由：未登录时返回本地状态 + 服务端代查的详情，保证按钮初始态可见。

### 2.2 点击行为

同一个按钮做开关（toggle），按按钮当前状态决定请求方法：

| 操作 | 未开启时 | 已开启时 |
| --- | --- | --- |
| 点赞 | `POST /api/like`（body 含 ID） | `DELETE /api/like?id=<ID>` |
| 关注 | `POST /api/follow`（body 含作者 ID） | `DELETE /api/follow?userId=<作者ID>` |

按钮文案随状态切换：`❤️ 点赞` ↔ `❤️ 已点赞`、`+ 关注` ↔ `✓ 已关注`。成功后由后端返回值决定最终显示，失败保持原态并提示。

### 2.3 冷却

每次点击后按钮禁用 3 秒。这两个接口会真实调用远端站点，冷却用于防止误点连续请求。

### 2.4 后端链路

| 步骤 | 点赞 | 关注 |
| --- | --- | --- |
| 远端调用 | 点赞 / 取消点赞接口 | 关注 / 取消关注接口 |
| 本地状态 | `markLiked` / `markUnliked` | `markFollowed` / `markUnfollowed` |
| 路由 | `POST` / `DELETE /api/like` | `POST` / `DELETE /api/follow` |

取消关注能力是后补的：远端取消关注接口与本地状态方法同时补齐，与已有点赞的一对接口保持相同形状。

## 三、搜索列表标记

搜索结果每行的「已赞」标记读取搜索数据里的 `liked` 字段（单一数据源），不再依赖前端内存中的全量集合做兜底。字段由服务端在返回前合并本地状态生成，详见 `搜索列表.MD`。

## 四、边界

1. **未登录**：点赞/关注接口返回 401，前端提示未登录；播放页按钮初始态仍可显示（本地状态）。
2. **作者 ID 缺失**：关注按钮拿不到作者 ID 时直接提示，不发请求。
3. **状态不同步**：远端成功但本地写盘失败时，以远端返回为准显示，本地在下次同步时纠正。
4. **限频**：官方接口有速率限制，冷却期内的点击直接忽略。
5. **措辞**：远端语义是「点赞」（like），界面与文档统一用「点赞」，不使用「收藏」。
